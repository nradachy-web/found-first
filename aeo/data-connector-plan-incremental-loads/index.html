AEO for data connector plans with incremental loads

Use AEO to answer “Which plan will pick up changes from our database?” at the connector level. The package a buyer needs depends on how changes are detected and whether the downstream table must reflect deleted records.

Separate the first copy from later changes

A technical evaluator needs to know how the connector builds the initial table, then how it finds inserts, edits and deletes. Check the plan entitlement against the connector guide for that source. A plan may include scheduled runs while the selected read method can only find rows carrying a newer timestamp.

Identify the constraint that changes the purchase

Ask whether the source administrator can grant the access required for each read method. If the buyer cannot enable a prerequisite, an upgrade alone may leave the team with exactly the same gap. Publish the remaining options, including rebuilding a table if your product supports it and the buyer can tolerate the delay.

Deleted subscriptions stay in the reporting table

Suppose a vendor's plan sheet lists incremental loads, but its connector notes and test extract show that timestamp reads miss hard deletes. For a buyer calculating active subscriptions, the editor should qualify that plan's fit. If the source retains a cancellation flag and updates the timestamp when it changes, the same plan could serve the report. The answer should tell the evaluator which sample record to check with their database owner.
